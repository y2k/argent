# local-unit-testing Specification

## Purpose

Позволяет разработчику проверять Java-target приложения локально одной командой, запускающей сгенерированные исходники тестов на JVM без Android-среды.

## Requirements

### Requirement: Запуск исходных Java-файлов

Команда `make test` SHALL генерировать Java из актуальных Y2K-исходников приложения и тестов и запускать проверки через многофайловый source-file launcher `java`. Отдельный вызов `javac` и предварительно собранные классы приложения SHALL не требоваться. Тестируемая логика SHALL исполняться на JVM, а не через eval.

#### Scenario: Первый локальный запуск
- **WHEN** разработчик запускает `make test` с установленными JDK 22 или новее, Make, ly2k и пакетами проекта без ранее созданных результатов сборки
- **THEN** команда генерирует необходимые исходники Java и выполняет тесты через запуск исходного Java-файла
- **AND** отдельная команда компиляции Java не вызывается

#### Scenario: Изменение исходника
- **WHEN** после успешного запуска разработчик изменяет тестируемый Y2K-исходник или тест и повторяет `make test`
- **THEN** проверяется новая версия исходника, а не сохранённый результат предыдущей компиляции

### Requirement: Независимость локального запуска от Android

Локальный набор SHALL выполняться без Android SDK, Gradle, Docker, Python и подключённого устройства. Платформонезависимые сценарии SHALL использовать общий с приложением производственный код, а не его тестовую копию или имитацию Android.

#### Scenario: Среда только для локальных тестов
- **WHEN** доступны предпосылки локального запуска, но отсутствуют Android-инструменты, Python и устройство
- **THEN** `make test` выполняет весь локальный набор, включая логику QR-запроса
- **AND** APK не собирается и не запускается

### Requirement: Сохранение покрытия локальных сценариев

Набор SHALL сохранять существующие проверки регистрации операций, QR-запроса, примера QR, кнопки QR, счётчика и обработки очереди, а также фактического stderr операций, очереди и QR. Сценарии SHALL оставаться на Y2K и исполняться через Java-target.

#### Scenario: Полный набор
- **WHEN** запускается `make test`
- **THEN** выполняются все сценарии шести прежних eval-групп и прежней проверки логирования
- **AND** сохраняются проверки отложенности, окружения, результатов, однократной доставки, остановки и поздних callbacks, порядка обработки очереди и вызовов эффектов

#### Scenario: Проверка вывода
- **WHEN** тест исполняет операции, проход очереди или QR-запрос
- **THEN** проверяются реально записанные в stderr строки и их порядок, включая отсутствие записей в ранее проверяемых пустых сценариях

### Requirement: Результат запуска и интеграция с check

`make test` SHALL завершаться с нулевым кодом только после успешного выполнения всего набора и сообщать об успехе. Нарушение проверки или ошибка генерации, компиляции либо исполнения SHALL давать ненулевой код. `make check` SHALL запускать этот набор перед существующими проверками Git diff.

#### Scenario: Успешные проверки
- **WHEN** все сценарии проходят
- **THEN** `make test` сообщает об успехе и возвращает нулевой код

#### Scenario: Нарушенное ожидание
- **WHEN** ожидание одного из тестов не выполняется
- **THEN** `make test` возвращает ненулевой код и выводит сообщение, позволяющее определить нарушенную проверку
- **AND** общий успех не сообщается

#### Scenario: Ошибка Java-target
- **WHEN** генерация Java или компиляция либо исполнение требуемого класса завершается ошибкой
- **THEN** команда возвращает ненулевой код с диагностикой соответствующего инструмента

#### Scenario: Полная проверка репозитория
- **WHEN** разработчик запускает `make check` и локальные тесты проходят
- **THEN** после JVM-набора выполняются `git diff --check` и `git diff --cached --check`
