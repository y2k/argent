# Proposal

## Why

Регистрация платформенных действий в `app.clj` раскрывает внутренний контракт `(env, arg)`, а композиция `:chat:new-message` вручную передаёт окружение. Функции регистрации должны скрывать этот контракт, чтобы прикладной код описывал действия и их композицию без знания механизма исполнения.

## What Changes

- Добавить `fx/register` для обычных функций `arg -> result`.
- **BREAKING**: изменить `event/register`: вместо готовой операции он принимает функцию `arg -> effect`, передаёт ей аргумент вызова и исполняет возвращённую операцию с окружением текущего вызова.
- Перевести регистрацию обработчиков приложения и тестовых зависимостей с прямых записей в map на эти функции.
- Сохранить общий вызов через `event/dispatch`, явную сборку окружения и разрешение зависимостей при исполнении.
- Оставить доступ к `w` внутри инфраструктурных операций рендеринга; прикладные обработчики составлять через операции и `fx/next`.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `operation-dispatch`: разделить публичные контракты регистрации обычных действий и композиционных обработчиков; скрыть передачу окружения за адаптерами, сохранив результат, отложенное исполнение и подмену зависимостей.

## Impact

- `src/argent/vendor/effect.clj`, `src/argent/vendor/event.clj`: функции регистрации.
- `src/argent/main.clj`, `src/argent/app.clj`, `src/argent/vendor/chat.clj`: миграция регистраций и сигнатур; `vendor/view.clj` остаётся потребителем окружения внутри инфраструктуры.
- `test/argent/counter.clj` и связанные eval-проверки: обновление контрактов и проверки передачи аргументов, результатов и актуального окружения.
- Новые зависимости не требуются. UI, очереди, формат сохранённых событий и QR-сценарий сохраняют поведение.
