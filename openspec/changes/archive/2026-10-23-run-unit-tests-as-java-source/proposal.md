# Proposal

## Why

Сейчас `make test` проверяет Y2K через интерпретатор eval, тогда как Android-приложение использует Java-target. Локальные юнит-тесты должны проверять сгенерированный Java-код и запускаться стандартной командой `java` для исходного файла, без отдельного вызова `javac` и Android-инструментов.

## What Changes

- Перевести `make test` и вызывающий его `make check` на генерацию Java из Y2K и запуск через многофайловый Java source-file launcher.
- Перенести шесть существующих eval-групп и проверки реального stderr из `test/logging.py` на JVM, сохранив сценарии и ненулевой код завершения при нарушении проверок.
- Оставить тестовые сценарии на Y2K; добавить минимальную точку входа и проверки средствами JDK без тестового фреймворка.
- Выделить платформонезависимую логику QR-запроса из `qr_image.clj`, чтобы тесты использовали тот же код, что Android-приложение, без Android/GMS-классов.
- Обновить документацию локальных проверок и отделить их генерацию от Android-сборки. Eval допустим для генерации правил сборки, но не для исполнения тестируемой логики.

## Capabilities

### New Capabilities

- `local-unit-testing`: локальный запуск юнит-тестов Java-target из исходных Java-файлов, полнота существующих проверок и результат команды для разработчика.

### Modified Capabilities

Нет. Контракты операций, логирования и QR сохраняются; меняется способ их локальной проверки.

## Impact

Затрагиваются `Makefile`, конфигурация генерации Java в `build.clj` либо отдельном тестовом build-файле, `test/*.eval`, `test/logging.py`, Y2K-тесты, `src/argent/vendor/qr_image.clj` и новый модуль логики QR-запроса, `docs/testing.md`. Используются установленный JDK, `ly2k`, Make и существующие пакеты Y2K/runtime. Локальные тесты не требуют Python, Android SDK, Gradle, Docker или устройства. Извлечение QR-логики требует проверки обновлённого приложения на физическом устройстве при реализации.
