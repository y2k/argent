# Proposal

## Why

Сейчас `event/dispatch` вызывает и обработчики событий, и платформенные эффекты, а отрисовка зарегистрирована как событие только из-за потребности в окружении. Разделение публичного API сделает назначение вызовов явным и оставит эффектам простой контракт «аргумент → результат».

## What Changes

- **BREAKING**: `event/register` и `event/dispatch` предназначаются только для обработчиков событий; эффекты регистрируются через `fx/register` и вызываются через новый `fx/call`.
- Сохраняются общее `env`, отложенный запуск вызовов и композиция обработчиков через `fx/next`.
- Эффекты остаются обычными функциями одного аргумента. Возвращённая функция является значением и автоматически не исполняется; API составных эффектов не вводится.
- Изменение состояния, отрисовка, запуск QR, Toast и постановка события в очередь используют API эффектов. Окружение для отрисовки подключается при сборке приложения.
- Сохраняются очереди, формат сохранённых событий, порядок обработки и отрисовки, поведение счётчика, сообщений и QR, существующий формат диагностических записей.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `operation-dispatch`: разделение публичных контрактов событий и эффектов вместо универсального вызова, простые эффекты и композиционные обработчики событий в общем окружении.

## Impact

- `src/argent/vendor/effect.clj`, `event.clj`: регистрация и вызов соответствующих операций.
- `src/argent/main.clj`, `application.clj`, `app.clj`: миграция вызовов и сборка окружения.
- `src/argent/vendor/chat.clj`, `view_node.clj`, `toast.clj`: обычные эффекты отрисовки, вызов QR и уведомления.
- Существующие JVM-проверки регистрации, счётчика, очереди, QR и логирования, Android-проверки компонента и примеры в `docs/qr-image-button.md`.
- Новые зависимости и миграция SQLite не требуются. `event-logging` сохраняет требования к порядку и формату трассы для обоих API.
