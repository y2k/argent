# Spec Delta

## MODIFIED Requirements

### Requirement: Единый контракт операций

Система SHALL хранить события и эффекты в общем окружении, предоставляя отдельные публичные API регистрации и вызова для каждого вида. Вызов события SHALL исполнять вычисление, возвращённое обработчиком; вызов эффекта SHALL возвращать результат обычной функции. Публичные функции получают один аргумент без окружения. Обработчик события завершается до возврата, без списка действий для отдельного исполнителя.

#### Scenario: Передача аргумента и результата
- **WHEN** зарегистрированное событие или эффект вызывается через соответствующий API с аргументом
- **THEN** его публичная функция получает этот аргумент без дополнительного параметра окружения, а вызывающий получает результат исполнения

#### Scenario: Завершённое изменение состояния
- **WHEN** обработчик увеличения счётчика вызван при значении 7
- **THEN** к моменту возврата значение равно 8 без дополнительного исполнения возвращённого списка

#### Scenario: Раздельные вызовы в одном окружении
- **WHEN** обработчик увеличения и эффект изменения состояния зарегистрированы в одном окружении
- **THEN** обработчик вызывается через API событий, а изменение состояния внутри него — через API эффектов

### Requirement: Старт через общий механизм

Запуск экземпляра SHALL вызывать зарегистрированный обработчик старта через API событий с общим окружением экземпляра и создавать одно сообщение с текущим значением счётчика посредством эффекта добавления сообщения.

#### Scenario: Первый запуск
- **WHEN** новый экземпляр приложения запускается
- **THEN** появляется одно сообщение со значением 0 без отдельного исполнителя начальных эффектов

### Requirement: Регистрация обычного действия

Система SHALL предоставлять API регистрации эффекта как функции от одного аргумента к результату и отдельный API отложенного вызова эффекта. Регистрация и создание вызова не исполняют функцию. При запуске вызова с окружением система SHALL разрешить эффект из этого окружения, передать аргумент и вернуть результат без попытки исполнить его как операцию. Составные эффекты с автоматическим исполнением возвращённого вычисления не поддерживаются.

#### Scenario: Отложенное обычное действие
- **WHEN** зарегистрирована функция записи значения и создан её отложенный вызов через API эффектов
- **THEN** запись ещё не происходит
- **WHEN** этот вызов исполняется с окружением
- **THEN** функция записывает переданное значение и её результат возвращается вызывающему

#### Scenario: Функция как результат действия
- **WHEN** обычное действие возвращает функцию
- **THEN** вызывающий получает эту функцию без её автоматического исполнения

#### Scenario: Подмена эффекта перед запуском
- **WHEN** после создания отложенного вызова эффект подменён в окружении, переданном при запуске
- **THEN** вызывается подменённая функция с исходным аргументом, а исходная функция не вызывается

### Requirement: Регистрация композиционного обработчика

Система SHALL предоставлять API регистрации события как функции от аргумента к отложенному вычислению. Только при исполнении вызова события система SHALL вызвать эту функцию, исполнить возвращённое вычисление с окружением текущего вызова и вернуть результат. Обработчик связывает действия через композицию; вложенные эффекты вызываются через API эффектов и разрешаются из того же окружения, а не окружения регистрации.

#### Scenario: Аргумент определяет вложенное действие
- **WHEN** зарегистрирован обработчик, создающий вызов эффекта увеличения состояния на переданный аргумент, и он вызван с 3 при состоянии 7
- **THEN** возвращённое вычисление исполняется до возврата, состояние становится 10 и результат вызова равен 10

#### Scenario: Фабрика не вызывается заранее
- **WHEN** зарегистрирован композиционный обработчик и создан отложенный вызов события
- **THEN** функция обработчика ещё не вызывается и вложенные действия не исполняются

#### Scenario: Подмена после регистрации
- **WHEN** окружение с зарегистрированным композиционным обработчиком дополнено подменённым эффектом и вызов исполняется с этим окружением
- **THEN** возвращённое вычисление использует подменённый эффект, а исходный эффект не вызывается

## ADDED Requirements

### Requirement: Платформенные действия являются обычными эффектами

Изменение состояния, добавление и отрисовка сообщения, запуск QR, показ уведомления и постановка события в очередь SHALL вызываться через API эффектов. Добавление и отрисовка сообщения SHALL завершать изменение View до возврата и возвращать `nil`. Их зависимости SHALL привязываться к экземпляру приложения при его сборке, без регистрации составных эффектов.

#### Scenario: Отрисовка и работа кнопки
- **WHEN** эффект добавления сообщения вызван с деревом экрана
- **THEN** сообщение добавлено до возврата `nil`, а его кнопки используют окружение того же экземпляра приложения

#### Scenario: Постановка события не является его обработкой
- **WHEN** эффект постановки бизнес-события увеличения в очередь завершён
- **THEN** событие сохранено в прежнем формате, а счётчик меняется только после его доставки обработчику

#### Scenario: Асинхронный результат QR
- **WHEN** эффект запуска QR возвращает управление
- **THEN** результат сканирования доставляется позднее через существующий callback, а возврат из эффекта не считается завершением сканирования
