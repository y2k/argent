# Подход к разработке

- **Рабочая ветка:** новые задачи выполняем в основном checkout на `main` без запроса подтверждения. Другую ветку или worktree используем только по явному указанию пользователя.
- **Git-коммиты:** создаём только по явному запросу пользователя.
- **Android-устройство:** перед завершением любой задачи с изменениями приложения обязательно собираем и запускаем обновлённое приложение на реальном физическом Android-устройстве, проверяем изменённый сценарий и работоспособность приложения. Успешная сборка и автоматические тесты не заменяют проверку на устройстве. Эмулятор используем только по явному указанию пользователя; если физическое устройство недоступно, просим его подключить и считаем проверку незавершённой.
- **MVP:** реализуем минимальный набор возможностей для текущей задачи. Выбираем самое простое рабочее решение.
- **Success way + undefined behavior:** реализуем только основной успешный сценарий, считая предусловия выполненными. Поведение вне этого сценария не определяем; дополнительные проверки и обработку ошибок добавляем только по явному требованию.
- **Маленькие итерации:** каждую итерацию завершаем работающим продуктом. Перед завершением проверяем изменённый сценарий и работоспособность продукта.
- **Никаких заделов на будущее (YAGNI):** пишем только то, что нужно текущей задаче. Никаких абстракций, расширяемости, настроек и зависимостей «на вырост». Усложняем решение только при появлении реальной потребности.
