# QR с камеры

Компонент открывает готовый Google Code Scanner с живой камерой и автозумом и
передаёт хешмапу `{:err ... :value ...}` в `:onresult`. Listener возвращает операцию, выполняемую с
окружением приложения, как `:onclick` у обычной кнопки:

```clojure
[:qr-image-button {:text "Сканировать QR"
                   :description "Scan QR"
                   :onresult (fn [{:err err :value value}]
                               (fx/dispatch :ui:toast
                                            (case err
                                              :cancelled "Сканирование отменено"
                                              :scan-failed "Не удалось завершить сканирование"
                                              value)))}]
```

Поддерживаются обычные атрибуты кнопки, включая `:compact`. Строка передаётся
без разбора; ссылка не открывается, JSON остаётся текстом. Пример на главном
экране показывает результат через Toast, не меняя счётчик.

Listener вызывается один раз при завершении сканирования, после освобождения ресурсов:

```clojure
{:err nil :value "содержимое QR"} ; QR найден
{:err :cancelled :value nil}      ; пользователь закрыл сканер
{:err :scan-failed :value nil}    ; SDK сообщил ошибку сканирования
```

Наведи камеру на QR: результат приходит автоматически без нажатия затвора.
Пока читаемого QR нет, сканер продолжает работу и listener не вызывается.
При событии отмены пример показывает «Сканирование отменено»; можно сразу
запустить его снова. При ошибке SDK показывает «Не удалось завершить сканирование».
На проверенном Pixel «Назад» возвращает ошибку SDK, а крестик — отмену.
Выбора сохранённой картинки больше нет.

Технические имена `:qr-image-button`, `:qr:pick` и `vendor/qr_image.clj`
сохранены для минимальной миграции; теперь они запускают камеру.

## Предусловия

- Устройство с камерой и работоспособными Google Play services.
- Для успешного результата в кадре один читаемый текстовый QR.
- Для первичной загрузки модуля Code Scanner доступна сеть. Запрос ожидает
  готовности модуля, затем открывает камеру.

Распознавание работает на устройстве. Камерой управляет Google Play services;
приложение не запрашивает CAMERA и широкие разрешения медиатеки.
Один запрос выполняется за раз. Незавершённый запрос не
восстанавливается после уничтожения Activity. Ошибка задачи сканирования
возвращает `:scan-failed`; ошибки подготовки модуля и множественный QR вне scope.

## Проверки

```sh
make check
sh test/qr_component.sh DEVICE_SERIAL
python3 test/counter_device.py DEVICE_SERIAL
```

`qr_component.sh` собирает и устанавливает приложение и тестовый APK на указанное
физическое устройство. Проверяет настоящий Button: передачу хешмапы, обновление
listener/текста и отключение старой кнопки, включая результат отмены.
Реальное распознавание проверяется отдельно на физическом устройстве:

1. Открыть сканер, сначала не наводить его на QR; убедиться, что он остаётся открыт.
2. Навести на QR `https://example.com/item/123` на бумаге или другом экране.
   Дождаться автоматического возврата и сверить Toast, не нажимая затвор.
3. Повторить с `{"id":123}`; содержимое не разбирается, ссылка не открывается.
4. Закрыть крестиком: Toast «Сканирование отменено». Проверить «Назад»:
   если SDK возвращает INTERNAL, Toast «Не удалось завершить сканирование».
5. Снова запустить и успешно прочитать QR. Проверить новую кнопку после
   добавления сообщения и недоступность старой.

Автозум включён; он не гарантирует чтение при любом наклоне или размытии.
Отдельное воспроизведение первой загрузки отсутствующего модуля вне приёмки.

## Проверки камерной версии 2026-10-20

- `make build`, `make check`: прошли; проверены однократная доставка,
  отмена, повторный запрос и подавление событий после уничтожения владельца.
- `sh test/qr_component.sh DEVICE_SERIAL`: `OK (1 test)` на Pixel 9a,
  приложение установлено.
- `python3 test/counter_device.py DEVICE_SERIAL`: `device checks passed`,
  включая счётчик, очередь, пересоздание Activity, старые кнопки и историю.
- Новая кнопка после добавления сообщения открыла экран Google Play services
  с `Scan code`, `Close code scanner` и `Scanned by Google on behalf of Argent`.
- В установленном приложении нет CAMERA, READ_MEDIA_IMAGES и READ_EXTERNAL_STORAGE.
  В собранном коде включены QR-only и `enableAutoZoom()`.
- `make check` и `git diff --check` прошли после изменения; read-only ревью
  не обнаружило дефектов в согласованном сценарии.
- Финальная ручная проверка подтверждена пользователем: после инструкции
  сканирования URL/JSON получено подтверждение отображения результата;
  отдельно подтверждено успешное чтение после закрытия и повторного открытия
  сканера. Это подтверждение пользователя, а не автоматический тест камеры.

Уточнение после проверки пользователем: текст распознанного QR отображается.
Диагностика на Pixel выявила различие: системная кнопка «Назад» возвращает
`MlKitException` с кодом `13` (`INTERNAL`), `Task.isCanceled() == false`.
Крестик `Close code scanner` возвращает отмену; Toast «Сканирование отменено»
подтверждён скриншотом `.build/qr-camera-close-result.png` на сборке без
временной диагностики. Код 13 не позволяет отличить отмену от внутреннего
сбоя. Согласован и реализован результат `{:err :scan-failed :value nil}`
для ошибки задачи сканирования. После обновления APK «Назад» проверен на Pixel:
Toast «Не удалось завершить сканирование» (`.build/qr-camera-back-error.png`).
`make check` проверяет новый текст, однократную доставку и подавление поздней ошибки.

## История: проверки прежнего Photo Picker 2026-10-20

Ниже результаты старой реализации выбора картинки; они не подтверждают
работоспособность текущего камерного сканера.

Физический Pixel 9a, APK установлен через `make run`.

- `make check`: `qr request ok`, `qr example ok`, `counter ok`.
- `sh test/qr_component.sh DEVICE_SERIAL`: `OK (1 test)`.
- `python3 test/counter_device.py DEVICE_SERIAL`: `device checks passed`,
  включая очередь, пересоздание Activity, отключённые кнопки и 15 сообщений.
- Системный выбор реальных картинок дал точные Toast:
  `https://example.com/item/123` и `{"id":123}`. Ссылка не открывалась.
  JSON проверен после изменения счётчика, URL повторно — из нового сообщения.
- В разрешениях установленного APK нет CAMERA, READ_MEDIA_IMAGES или
  READ_EXTERNAL_STORAGE. Системный выбор не требовал широких разрешений.
- Скриншоты текущего запуска: `.build/qr-url-result.png`,
  `.build/qr-json-result.png`, `.build/qr-new-message-result.png`.
- `git diff --check`: без ошибок.
- После исправления пустого результата: на том же Pixel выбрана картинка без QR,
  приложение осталось в том же процессе без ошибок AndroidRuntime. Затем выбран
  QR со ссылкой, получен правильный Toast и проверено увеличение счётчика.
  Регрессионная проверка в `test/qr_image.eval` проверяет освобождение ресурсов,
  передачу `{:err :qr-not-found :value nil}` без QR и успешный следующий запрос.
- Контракт `err/value` проверен на Pixel: после картинки без QR показан Toast
  «QR-код не найден», после следующей картинки с QR — исходная ссылка.
  Скриншоты: `.build/qr-err-result.png`, `.build/qr-value-result.png`.

Картинки созданы локально через `qrencode -s 12 -o <file.png> '<text>'`,
скопированы в `/sdcard/Pictures/`, зарегистрированы broadcast
`android.intent.action.MEDIA_SCANNER_SCAN_FILE`, выбраны через Photo Picker.

**Историческая непроведённая проверка:** первая загрузка модели на физическом устройстве.
В проверенном запуске загружался доступный модуль Play services
`com.google.android.gms.vision.barcode:264032001`; отсутствие модели перед
запросом не установлено. Повторное распознавание подтверждено. Eval-проверка
ожидания подготовки не заменяет реальную установку. Пользователь исключил
эту проверку из scope; она не отмечается пройденной.
