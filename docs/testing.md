# Проверки

## Быстрые проверки на Y2K

Из корня проекта с установленными `ly2k` и Python 3:

```sh
make test
```

Команда запускает проверку логирования через Python 3 и шесть групп через `ly2k --target eval`, без APK и устройства:

| Группа | Что проверяет |
| --- | --- |
| `logging.py` | Реальный stderr: отложенность и вложенность операций, события очереди и QR |
| `registration.eval` | Регистрация, отложенность, композиция и подмена операций |
| `qr_image.eval` | Подготовка сканера, однократная доставка, отмена/ошибка, очистка и поздние callbacks |
| `qr_example.eval` | Передача исходного результата в уведомление |
| `qr_button.eval` | Вызов `:qr:pick`, listener и окружение нажатия в настоящем преобразовании узла |
| `counter.eval` / `argent/counter.clj` | Состояние, маршрутизация событий, изоляция экземпляров, аргументы и число вызовов эффектов чата |
| `event_pump.eval` | Настоящий проход очереди: handle → ack → render → wake, один элемент за проход, остановка на пустой очереди |

Используются обычные функции и `assert`. Ошибка завершает проверку ненулевым кодом. Исходники загружаются целиком в порядке зависимостей. Новые eval-only сценарии размещаются в `.eval`, чтобы Android-сборка не компилировала их как Java-target исходники.

В тестах чата записываются вызовы `:chat:append-message` и `:chat:render-message`. Заглушки не реализуют историю, лимит или отключение кнопок. Эти механизмы остаются в Android View-дереве.

`make check` запускает тот же набор тестов, затем `git diff --check` и `git diff --cached --check`.

## Проверки на физическом Android-устройстве

Для сборки нужен Docker с доступом к образу из `test/qr_component.sh`; для устройства — `adb` и `android` CLI. Выберите serial физического устройства из `adb devices -l`:

```sh
make build
android run --device DEVICE_SERIAL --apks .build/apk/app-debug.apk --activity 'argent.app$MainActivity'
adb -s DEVICE_SERIAL shell settings put system accelerometer_rotation 0
adb -s DEVICE_SERIAL shell settings put system user_rotation 0
python3 test/counter_device.py DEVICE_SERIAL
sh test/qr_component.sh DEVICE_SERIAL
```

`counter_device.py` проверяет реальные нажатия и burst-доставку, восстановление и очистку SQLite-очереди, recreation и единственного consumer, историю, отключение старых кнопок, прокрутку и лимит 15 сообщений. Начальная ориентация должна быть `0`: тест переключает её в `1` для пересоздания Activity. Скрипт перезаписывает очередь тестовыми событиями, перезапускает приложение и меняет ориентацию; запускайте на тестовом экземпляре приложения. Промежуточная арифметическая проверка одиночного decrement перенесена в eval; реальные decrement и отрицательное значение остаются в device-suite.

`qr_component.sh` собирает и устанавливает приложение и instrumentation APK, проверяет обновление текста и listener настоящей кнопки, передачу результата и отключение старой кнопки. Это не проверка камеры: `:qr:pick` здесь подменён.

Дополнительно на устройстве проверьте:

1. «Сканировать QR» открывает камеру; читаемый QR возвращает исходный текст в уведомлении.
2. Закрытие сканера крестиком сообщает отмену, повторный запуск работает. «Назад» может дать ошибку SDK — она отображается отдельно от отмены.
3. После уничтожения Activity незавершённый запрос не доставляет результат старому владельцу; новый экземпляр продолжает работать.

Eval проверяет алгоритмы, а сборка — Java-генерацию и SDK-связи. Проверки на устройстве подтверждают платформенное поведение; вызов эффекта в unit-тесте их не заменяет. Результаты автоматических device-проверок сохраняются в `.build/counter-device-check/` и `.build/qr-component-result.txt`.

- Независимое read-only ревью не выявило замечаний; все шесть eval-групп повторно прошли.

Флаги `--activity-*` должны идти после `-f`. Первоначальная попытка через `settings put global always_finish_activities 1` не уничтожила Activity; настройка возвращена в исходное значение `0`.
